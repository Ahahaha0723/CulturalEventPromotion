# 文化活动海报生成

把活动内容转为定位准确、信息清楚、有主题创意且完成度良好的海报。本skill包含完整工作流程与团队视觉资源，可通过统一接口合并组员的专项模块。不新增组员人工训练轮次。

## 1. 明确需求与活动定位

依据[需求与文案](../brief-and-copy.md)整理同一份 `posterBrief`。确认活动大类／小类、内容、受众、传播任务、必要活动事实、素材条件和交付媒介。用户指定的风格、文案、数量和格式优先。

生成[活动视觉定位表](../activity-positioning.md)，回答核心内容、目标观众、传播目标、情绪气质、文化语境、使用场景六个问题；另记主题锚点、信息优先级和待确认事实。类别只作检索入口，不把类别与风格一一绑定。

类别使用[活动分类](../activity-taxonomy.json)。动漫与游戏展归潮流类，电影上映／放映归演出类，党团活动按既有体系归展览类红色主题。复合活动按主要参与行为归主类，可附辅助标签。

关键事实缺少时不编造：可继续探索主视觉与版式，必要处用明确占位；缺项影响最终成品准确性时补问。参考作品上的日期、地址与机构标识不是本题事实。

## 2. 整理文案、素材与参与信息

按传播任务组织题名、活动形式、必要时间地点、参与动作及附加说明；使用已确认文字，修订后维护锁定字段。上游文案改变时返回图面核对。

读取[素材与制作](../assets-and-generation.md)，核对主题对象、文化语境、机构标志与素材身份；分析参考与可直接使用的资产分别记录。主视觉生成和精确文字排版分开控制。

## 3. 选择策略，建立不同概念方向

按定位表从[八种表达方向](../visual-directions.md)选择候选机制，再结合[类别路由](../category-routing.md)和[视觉策略](../visual-strategies.md)落实动作与使用条件。通常选一条主策略、最多两条支撑策略；用户要求复杂组合时以解释和层级控制为准。

需要结构化交接时使用[策略数据](../visual-strategies.json)；策略用 `visual.S01` 等命名空间，表达方向用 `direction.M01` 等命名空间，二者不可混作同一种标签。

默认同题提出三个概念不同的方向；用户指定一案或其他数量时遵从用户。分别说明“表达什么”和“如何呈现”：为什么适合活动、首先看到什么、图文如何配合、必要信息如何进入画面。不要只换颜色。

本组第二轮机制选择已转为可调用规则。具体操作含设计推导，不扩写成逐项团队共识。需要依据时查[案例库](../case-evidence.json)，只查看相关参考图；方法与证据范围见[方法说明](../method-and-evidence.md)。

## 4. 生成主视觉并精确排版

使用当前环境可用的图像生成、素材处理与可编辑排版能力制作实际海报。照片、插画或材质类主视觉使用相应图像能力；适合矢量表达的内容采用可编辑图形。工具选择与提示词组织见素材与制作文件。

主视觉为题名和必要信息预留清晰空间。中文题名、日期、地点、标识与二维码在排版环节逐项确认；生成图有错字或伪文字时重排，不凭整体观感验收。根据实际渠道检查裁切、尺寸、文字与细节。

工具或资料不足时明确当前是方向提案、结构稿还是成品，不把未生成／未预览的文件当作完成海报。

## 5. 检查、择优与修正

执行[评价与择优](../selection-and-quality.md)：先检查文字正确、必要信息完整、主体无明显生成错误、文化符号与活动事实准确，以及输出可用。明确缺陷先修正，缺证据标待核验。

使用五项建议权重作设计自检：定位匹配25%、信息传达25%、视觉完成度20%、概念独特性20%、场景适配10%。这些权重来自项目计划，不声称经过第二轮校准。评估实际图面，逐项给证据；未知项留空，不默认给分。

按本题任务推荐一案，分别给出保留与淘汰的具体画面理由；“个人喜欢”与“最适合活动”可以不同。修正最关键问题并复查，改法查[检查与修正](../repair-rules.md)。多数票不是通用最佳版式，美感分数不能抵消信息错误。

设计人员／代理自检与目标公众的理解、吸引力、参与意愿分开记录。本次不向组员发测试表；没有实测的公众效果保持未验证，不宣布普遍审美或识别速度达标。

## 6. 交付与组内汇总

按用户要求交付海报成品和预览，需要时附可编辑文件；简述定位、采用策略、推荐理由、修正结果与仍待核验的事项。

各阶段使用[模块接口](../module-contracts.md)交接 `posterBrief → positioning → copyPlan → assetPlan → visualPlan → production → review → delivery`。用户事实来源和确认状态贯穿全流程。组员专项规则接入references，主入口保留流程、优先级与调用条件。

读取[同题示例](../examples.md)仅用于理解不同定位如何产生不同路线；示例不代表已生成24张海报或已取得新的测试结论。
