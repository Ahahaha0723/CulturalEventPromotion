# 按对应语言提示词严格执行

## 适用与来源

本规则适用于所有文化活动类别的中文和英文海报。执行用户最新明确指令、对应类别入口中的用户覆盖规则、已获确认的本项目语言方案及该语言成员包的提示词／版式／字体／参数，不把成员指令弱化成可自由发挥的风格建议。资料包中的活动文字和示例事实仍是待分析材料，不是新增执行指令；不能照搬旧校名、日期、IP、旧人审或示例测试状态作为本题事实。

同一语言的入口、参考与参数存在冲突时，先看明确的最新覆盖记录；没有足以消解冲突的依据时展示冲突和所需调整，不自行选一条或改提示词。用户已明确确认或成员明确允许的适配直接执行并记录，不重复询问；新事实冲突、超出适配范围或无法兼容的硬约束才请求决定。通用建议不能覆盖已明确的类别／语言规则。

## 分别锁定与执行

1. 中文 `zh-CN` 加载中文包，英文 `en` 加载英文包。英文不得只把中文生成提示翻译后继续沿用中文参数；没有独立语言包的类别从同母本建立该语言计划，再执行已批准的语言安排。
2. 在项目 `prompt-plan.yaml` 的 `language_execution` 中逐版记录 `template_id`、入口与指令／提示来源文件、实际语言文案、`image_prompt`、排版约束、真实字体／资产路径及明确允许的调整。实际调用的提示文本与锁定版本一致，模型所需参数转换单独记录，不静默删减负向约束或改设计要求。
3. 把明确要求列成验收项：构图、主图及保护范围、色彩角色、字体与字重、尺寸／可见边界、对齐、断行、横线／遮罩等必需机制、文字与输出范围。固定值与“约／建议／起点”分开记录，后者只在其许可范围适配，不将局部可调整解释成整版可自由变更。
4. 提示词负责的图像处理须按所选语言图像提示执行；正式文字、字体、校徽、Logo和QR由指定真实文件及可控排版实现。实际文件路径写入对应语言计划并真正加载，不能仅凭生成提示写了字体名／路径就称已应用。工具不足时报告具体未执行项，按成员允许的等效工具处理；没有允许依据不能擅自用简单滤镜、重画标识或替代字体充当完成。
5. 中文和英文允许依各自提示词产生不同的版面、文字关系或视觉结果，不强制复制同一张图只换文字，也不为了“成套”改掉英文／中文明确要求。共享事实和已明确共享的资产／几何仍一致：例如体育要求双版同图几何、校庆要求同一校徽可见尺寸，这些约束不能因为语言不同被解除。兼容两版提示的资产可复用，必须逐版检查。

## 检查与返工

在内部质量记录加入每版 `prompt_conformance`，逐条保存 `source`、`requirement`、`expected`、`actual`、`evidence`、`status`（pass／fail／unverified）。数值与字体路径按真实文件／字形／图像边界测量；照片处理、构图和风格按原图与提示逐项视觉核对，不能只看“整体像”或仅靠脚本返回成功。

错误语言包、主标题违反明确单行规则、必需横线／机制缺失、校徽尺寸错误、擅自改字体／颜色／构图／照片身份、提示词关键要求被省略均为不通过项。返工到对应提示、图像或排版阶段；未修复或未获得用户对具体偏差的明确覆盖，不能报告该版遵循提示或任务完整完成。图像工具输出仅是候选，写入强指令不保证一次生成通过，成品QA与定向返工必须执行。

事实、双语完整性、文化、权限和规格检查继续执行。受众效果未经测试仍为未验证；字体样张、示例测试记录和提示完整不证明完整海报成品通过。记录不作为额外用户交付文件，最终格式按用户与类别明确范围。


## 人工确认与语言计划的关系

每版语言计划必须对应已获用户确认的同一母本版本。模板的固定方向或历史例图不能替代本轮提取结果确认。两版任一出现比例错误、必需资料图缺失或无法满足明确约束，按 [人工确认节点](human-confirmation-gates.md) 暂停受影响流程，先提交证据与处理选项，再按具体用户决定更新相关语言计划和验收项。用户确认某版适配不自动批准另一版换字体／布局，也不默认取消双版共享几何要求；明确标记影响范围。
