# 人工确认节点

本规则适用于全部十四类及其中文、英文版本。它补充现有事实、方向和交付 Gate，不替代类别规则。以下确认针对实际海报项目；不是要求修改 Skill 文件时再次确认。

## A. 内容母本提取结果确认：每个新项目必经

资料解析、母本归一化和自动检查完成后，先展示可审阅结果，再明确请求用户确认或修订。即使所有字段都能从原文找到、脚本返回 PASS，也不能省略。未获确认时可以继续盘点和检查文件、分析类别或测量已有资源，不能进入依赖母本的视觉方案制作、图像生成、正式排版或终稿导出。

展示内容包括：

- 提取信息表：字段、实际值、来源位置（文件／页码／图片区域／用户消息）、状态。按本项目提供的信息列出活动名、主题／宣传语、日期时间、地点、组织角色、参与信息及必要专名，不强行补齐不适用字段。
- 拟上版文案与信息层级：明确哪些显示在海报，哪些仅作视觉上下文，哪些不显示及依据；不要把未上版的事实从母本删除。
- 缺失、冲突、低置信度和待确认翻译：保留原文、候选值及具体疑点；无问题时明确“未发现待核实项”。
- 素材清单：实际可用的资料图、校徽／Logo、二维码与字体；区分必需、可选和缺失，不把风格参考当活动原始素材。
- 语言版本、所选类别、画布比例／真实尺寸、输出格式和数量；来源是用户要求、类别例外还是默认值须明确。

确认请求示例：“以上是本轮提取的内容母本 v01 和拟上版信息，请确认内容、信息取舍及输出规格，或列出需要修改的项。确认后再进入海报制作。”展示必须包含本项目实际结果，不能只发空模板或泛泛询问是否继续。

用户可以整体确认，也可以逐项修改。先写回修改、更新版本并展示受影响内容，再确认尚未批准的变化。已有用户对同一版本、同一范围的明确确认直接继承；不能要求重复批准，也不能把“请制作海报”、选择风格或批准旧案例当作批准尚未展示的新提取结果。用户在看过结果后明确指示“按这些内容制作”可作为该范围的确认。

沉默、等待时长、模型自行判断、自动检查通过和历史模板测试不构成人工确认。某个缺项若经用户明确同意暂时留空／占位，只能按已确认范围制作审阅稿，事实状态仍为 `missing`／`pending`，不能记成真实事实已确认。

## A1. 主体素材使用范围

当资料有多个适用主体图且使用数量/范围未明确时，展示编号总览，询问使用数量、选择范围和用途，按[素材数量与拼贴](asset-usage-and-collage.md)记录asset_usage。用户已指定编号或数量与AI择图范围时直接复用；无需重新确认未变事实。多个已选主体要在拼贴或其他已确认用途里逐项核对，不能静默缩减为一个。

## B. 严重制作问题确认：首次发现即触发

以下情况暂停受影响流程，不等到连续两轮返工：

| 严重问题 | 展示给用户的具体证据 | 可供选择的处理方案 |
|---|---|---|
| 海报成品或拟采用整版结果比例／尺寸与已锁定要求不符 | 要求值与实际文件尺寸、比例及预览；例如要求 4:5／2400×3000，实际为 2:3／2400×3600 | 按原规格重新生成／排版；采用已说明的裁切、扩展画布等方案并保留原规格；由用户明确批准改变输出规格 |
| 必需资料图、校徽／Logo、指定参考或授权素材缺失／不可读／身份无法核实 | 缺少的文件及其用途、为什么属于必需、受影响区域 | 补充正确资料；使用用户明确指定的替代资产；明确批准留白／占位或适用的原创方案 |
| 必需字体／字形、成员模板或关键工具不可用 | 路径、检查结果、无法执行的具体要求 | 补齐资源；使用规则允许且能满足约束的等效工具；用户明确批准具体替代／调整 |
| 锁定事实、文案、单行要求、可读性或布局范围无法同时满足 | 实际文案、测量／预览、发生冲突的规则 | 在原允许范围内重排；由用户决定具体内容或规格调整，保留其确认依据 |

无文字配图的素材尺寸不等于最终海报尺寸：若原计划已允许按既定规则放入锁定画布，且不损伤必需内容，就正常合成，无须把每张素材的比例差异当严重问题。可选配图缺失、字体样张可通过真实工具重测、允许范围内的行距／对齐／普通排版修正可自行处理。必须使用的真实校园图、作品或标识不能因模板另有缺图示例就自动改成留白；须先呈现本次缺失并确认。

确认时说明“问题、要求与实际、影响、推荐处理和其他可执行选项”，提供已有预览或资源检查证据。请求的是具体方案，而不是笼统地问“是否继续”。首次发现后，未获决定前不继续生成／合成受影响部分、不交付不合规终稿；独立的资料盘点和检查可继续。不得擅自拉伸成品、改比例、删除必显内容、生成假校徽／Logo，或用风格参考代替真实资料图。

如果当前会话已经明确批准同一问题的同一处理方案，记录并执行，不重复询问。没有明确批准时不能把时间流逝当同意。用户选定方案后实施、复检并记录：批准修改要求时先更新母本、语言计划和验收值；批准按原要求重做时保留原验收值。批准“继续”不自动使错误结果通过 QA。方案仍失败或产生新的严重问题时重新提交具体问题，不无限随机重试。

## 确认记录与恢复条件

母本内 `human_review.content_master` 保存当前内容版本、待确认／已确认状态、已确认版本、确认范围、用户消息来源和决定。只有能追溯到真实用户回复时才填 `confirmed`。后续关键事实、拟上版取舍或规格变化递增版本，使受影响确认回到 `pending`；不重新确认未变化的部分。

严重问题记入 `human_review.production_issues` 并关联质量报告，至少保存：问题 ID、阶段、严重度、要求值、实际值／证据、选项、状态、用户消息来源、选定方案、回退目标和复检结果。状态依次为 `pending_confirmation` → `approved` → `resolved`；用户不批准时保持阻断，不伪造已解决记录。

母本已确认当前版本，且所用处理方案有有效用户决定、相关严重问题复检通过后，才恢复受影响制作。交付前必须核对这些记录；`validate_brief.py` 和 `validate_delivery.py` 的成功只说明其自动检查通过，不能替代真实人审证据。
