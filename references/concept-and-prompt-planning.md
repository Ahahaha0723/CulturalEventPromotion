# 视觉概念与生成指令规划

## 从资料到概念

使用以下链路，避免“列元素后直接套风格”：

```text
文化事实与活动目标
→ 文化/传播洞察
→ 核心设计命题
→ 视觉隐喻或母题
→ 构图与素材机制
→ 生成提示和负向约束
```

核心文化判断记录来源和证据等级：A 为用户指定或官方资料，B 为可靠学术/专业资料，C 为当代设计参考，D 为未经验证的联想。核心识别优先使用 A/B；D 不承担历史事实或主要文化识别。

## 概念方向

一般提出 2–3 个结构真正不同的方向。每个方向说明：名称、设计命题、文化依据、视觉母题、主体、构图机制、素材计划、传播优势、风险和适用媒介。方向差异应来自洞察、观看尺度、空间组织、叙事或媒介机制，而不只是换色和换字体。

## 提示计划

从 `assets/prompt-plan-template.yaml` 复制。将提示拆为：任务目标、主体、场景、构图、媒介/材质、光线、色彩角色、文化约束、预留文字区、输出比例和负向约束。

负向约束至少排除：随机文字、伪 Logo、伪二维码、无关文化符号、刻板化“东方”装饰、无依据历史混搭、异常人体/结构、过度细碎背景和侵占正式文字安全区的元素。

## 人工确认点

在高成本生成前确认：主方向、文化元素、素材授权、画布比例和正式文字预留。文化敏感性、宗教/民族符号、文物形制和官方身份不得由模型单独批准。

## 已指定模板的概念规划

艺术街区、工作坊与体育赛事已由用户锁定成员设计，必须执行 [类别模板路由](category-template-routing.md)。不再提出替代固定版式的自由方向或重复请求风格确认；概念规划只确定与母本对应的动作、物件、抽象关系和模板允许的主题色。事实、文化、授权及超出模板容量的具体调整仍按原确认规则处理。

## 锁定每版实际提示

所有类别按 [语言提示词执行规则](language-prompt-execution.md) 在项目提示计划中分别建立 `language_execution.zh-CN` 和 `.en`，保存该语言入口与提示来源、实际图像提示、排版约束、真实资产路径和允许适配。生成调用不能静默精简／改写已锁定的硬约束。校庆现沿已选成员固定方案规划，不另选旧入口自由版式；英文单行标题等按英文包执行，不从中文参数派生替代。
