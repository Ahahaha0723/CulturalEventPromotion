# 动漫／游戏／IP体验展

## 类别与边界

- 观看、试玩、展陈、角色互动与创作者交流为主时保持 `primary_type: exhibition`。竞赛／电竞竞技为主走 [体育赛事入口](sports-event.md)，文化品牌快闪按真实主要行为分流；不凭“二次元”或数码媒介直接选霓虹风格。
- 路由漫展 `anime-convention` → `anime-character`、游戏展 `game-expo` → `game-modular`、IP体验 `ip-experience` → `ip-portrait`、创作者摊位／Artist Alley `artist-alley` → `artist-alley`。招募／摊位公告的行动目标与主展宣传不同，不能未经说明用公告结构替代整场展览海报。
- 活动名与核心体验 > 日期、场地 > 真实 IP／展区／嘉宾 > 试玩、签售／摊位或参与条件 > 票务与机构。保留原观看／互动边界，不虚构官方IP、角色、游戏内容、嘉宾、联名、试玩名额或授权关系。

制作前必须分别读取[中文三案例规则](../../assets/category-templates/anime-game-expo/zh-CN/references/case-guided-generation.md)与[英文三案例规则](../../assets/category-templates/anime-game-expo/en/references/case-guided-generation.md)，实际查看three-case-index中的P700、P705、P96原图。按真实活动选择主参考与支撑：综合漫展的互动群像／城市与独立信息带，单IP的眼神／题名双焦点与材质，创作者公告的叙事／署名与真实摊位定位。主视觉、风格和文字分别记录“观察机制→本案关系→制作动作→成稿对照”，落实到图像提示、真实文案与完整／缩略成稿审核；支持参考输入时传入实际图片，否则记录限制并使用具体观察描述。

不机械拼接三种构图，不迁移角色、日期、城市、Logo或摊位事实；综合游戏展仍按真实玩法与展区局部迁移，044缺图状态保持。P96原评分分歧及拥挤小字限制保留，不宣称其是综合展成功验证。新artist-signature调度英文署名的真实Spectral Italic，artist-alley英文subtitle调度真实Barlow BoldItalic（正常字宽，不能自动替换为窄体）；实体与字形以catalog和实际返回路径核验。中文自然字宽重排，英文保护完整词与语义，不压扁字形或机械拆城市名；两版严格执行各自提示及[逐语言执行核验](../language-prompt-execution.md)。

## 严格参考字体与排版（2026-10-13新版）

默认必须分别执行[中文严格参考规则](../../assets/category-templates/anime-game-expo/zh-CN/references/strict-reference-typography.md)和[英文严格参考规则](../../assets/category-templates/anime-game-expo/en/references/strict-reference-typography.md)。先实际看图并比较活动形式、文案量、语言、画布与气质，选一个有依据的主文字参考；再锁定标题、活动形式、传播语、日期、正文与CTA的字形、真实粗细宽窄、可见比例、对齐轴、间距、换行和图文交接。原图没有的角色延伸已有系统，不能无依据新增字族或斜体。参考022的中文应比较几何粗黑／受控构字，不能因为国漫就默认庆科黄油体；053摊位文字使用正常字宽粗斜体候选，不能混同窄体。

原字体未确证时必须制作原图局部、实际文案候选和成稿文字区并列对照，记录差异与选择理由，不宣称精确原字体或虚构匹配分数。逐语言保存typography-reference-lock，使用包内scripts/reference_font_check.py核验显式锁定文件的哈希、许可和整字段覆盖，禁止静默回退。共享字体从catalog实际路径加载，工具仅允许资源落在整个cultural-event-poster包内。通用候选调度／缺字检查不能代替严格参考匹配；必要语言／比例／可读性变动逐项说明。此前国漫风起v01不作为字体或信息带比例默认模板，不把旧技术通过升级为新标准通过；本次只更新规则，不重做旧海报。

## 接入总流程与双语交付

本类别必须读取上述两套成员入口及其要求的事实、子类、双语、字体、案例转化、生成前确认和 QA 文件。强制执行成员策略与专项规则；成员提供的是条件方案，不将参考样图编造为所有小类唯一版式。总 `SKILL.md`／`SKILL.en.md`、统一 `brief.yaml`、现有 Gate 和默认2400×3000／4:5规格保持。成员母本与记录是派生材料，事实冲突回到总母本修正；成员默认单语标识不覆盖所有文化活动同时交付中文 `zh-CN` 与英文 `en` 两版完整海报的要求。

主方向、文化／身份元素、素材授权、画布与范围、正式文字预留五项接入现有方向 Gate，以可读表格展示。已获用户明确确认的事项直接继承，只确认变化或尚未解决的项；试稿授权不证明未知事实、官方身份或素材权限。模板 JSON、成员历史 QA 和评分记录不能填写为本次人审通过或公众效果证据。

制作前实际查看 `assets/case-manifest.json` 中 `package_image` 指向的参考图，读取案例转化与对应小类路线，记录参考角色、借鉴机制与本题落地方式。保留原评分、缺项和邻近参考的证据层级，不照抄活动名称、阵容、节目、日期、IP、Logo 或原图。历史 Windows 路径仅为来源记录，运行时使用包内相对路径。

### 字体与执行路径

资源基准为所选成员 `SKILL.md` 所在目录。字体实体与许可证按哈希去重到总包 `assets/fonts/performance-anime-members/`，每个成员的 `assets/fonts/catalog.json` 保存实际相对 `file`／`license_file`、原路径、官方来源与原哈希。`role-profiles.json` 和角色索引中的字族／文件标识是候选 ID，实体位置以 catalog 为准，不拼接旧目录，不依赖系统安装。当前新包字体版本独立于红色主题字体；红色模块两项现已由用户另行补交原版，具体状态和路径以其最新manifest为准，不交叉覆盖版本。

在项目工作区调用所选包内 `scripts/font_engine.py --profile <方案ID> --language zh-CN|en --role title|subtitle|body|numeric --text-file <真实文案文件>`，脚本完整路径决定模块根目录。按实际返回路径加载字体，记录内部名称、字重、哈希、字段字形覆盖及回退原因；整体字段无覆盖候选时停止该字段排版，不静默使用系统字或方框。字体匹配只是技术候选，真实文案至少比较两个题名样张，全幅与缩略图均需检查。字体样张、项目母本和输出写入项目工作区，不写回资源目录。

默认先制作无正式文字的主视觉，再可控排版。原创题名图形是成员案例转化允许的有限例外：只作用于本活动原创题名，逐字、身份和可读性核验后使用；日期地点、节目／阵容、费用、机构、Logo 与二维码仍用准确文字或真实资产。不能以例外替代全部正式排版。

### QA 与交付

主流程根目录的 `scripts/validate_brief.py` 和 `scripts/validate_delivery.py` 是母本及最终交付的权威检查，强制双版、规格和完整成品要求保持。成员同名脚本保留为辅助检查，不能用较宽松的成员检查替代总 Gate。字体调度器不是完整海报生成器，旧样张与旧 QA 不是新活动端到端成品测试。

执行成员事实、文化／IP、字形、阅读路径、层级、背景对比、实际边界、画布与移动预览专项检查。关键事实错误、身份误置、缺字、严重不可读、授权阻断或规格错误阻断终稿。审美自检与观众传播效果分别记录，未测试保持 `not-tested`；条件策略维持成员 `trial`／`pending-case` 状态，不因合并或技术测试升级。只修改文字关系时保留认可主视觉，按受影响阶段定向回退。

共同执行 [类别模板与模块路由](../category-template-routing.md)、[双语内容规则](../bilingual-content.md) 和总 QA，不另建主流程。公开发布或上传仍需用户明确要求。
